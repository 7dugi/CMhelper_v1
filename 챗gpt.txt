전체적으로 보면 상당히 잘 정리되어 있습니다.

특히 일반적인 개발 문서가 아니라 **"AI와 장기간 협업하기 위한 운영체계"** 관점에서 작성된 점이 좋습니다.

현재 상태라면 80~85점 정도이고, 실제 SaaS 운영까지 생각한다면 몇 가지를 추가하는 것이 좋겠습니다.

---

# 가장 먼저 추가할 것

## 1. 의사결정 기록 문서 (ADR)

현재 문서 구성

```text
PROJECT_OVERVIEW.md
ARCHITECTURE.md
CURRENT_STATUS.md
TODO.md
CHANGELOG.md
```

여기에

```text
ADR.md
```

를 추가하는 것을 추천합니다.

ADR = Architecture Decision Record

예시

```md
2026-07-16

주제:
카카오톡 자동화 구현 방식

선택:
pywinauto + OpenCV

배제:
PyAutoGUI 단독 사용

이유:
해상도 영향 최소화
유지보수성 향상
```

---

AI는 6개월 뒤에

```text
왜 OpenCV 썼지?
왜 Electron 안 썼지?
```

를 기억 못합니다.

ADR이 있으면

```text
왜 그렇게 결정했는지
```

를 보존할 수 있습니다.

이건 실제 개발팀도 많이 씁니다.

---

# 2. Definition of Done 강화

현재도 있지만 조금 더 구체화하는 것이 좋습니다.

현재

```text
빌드 및 실행 테스트 성공
```

↓

추천

```text
Definition of Done

- 코드 작성 완료
- 예외 처리 완료
- 로그 출력 확인
- 로컬 테스트 성공
- 문서 업데이트 완료
- Git 커밋 완료
- CURRENT_STATUS 갱신
- CHANGELOG 갱신
```

---

이렇게 해야

```text
코드는 됐는데 문서는 안 바뀜
```

을 방지합니다.

---

# 3. "AI 금지 행동" 추가

이건 꼭 넣는 게 좋습니다.

예시

```md
AI Forbidden Rules

금지사항

1.
작동하는 코드를
추측으로 리팩토링하지 말 것

2.
사용자 승인 없이
기존 구조를 대규모 변경하지 말 것

3.
문서와 다른 구조를
임의로 생성하지 말 것

4.
환경변수(.env)를
직접 출력하지 말 것

5.
작동 중인 기능을
최적화 명목으로 변경하지 말 것
```

---

AI는 가끔

```text
더 좋아보이는 구조
```

를 만들다가

```text
기존 기능을 깨뜨리는 경우
```

가 있습니다.

이걸 막아야 합니다.

---

# 4. Rollback 규칙 추가

지금 문서에는 롤백 개념은 있지만 절차가 없습니다.

추천

```md
Rollback Policy

중대한 오류 발생 시

1.
마지막 안정 버전 확인

2.
Git Tag 확인

3.
즉시 롤백

4.
원인 분석

5.
새 브랜치에서 수정
```

예시

```text
stable-v0.4
stable-v0.5
stable-v0.6
```

---

# 5. 로그 정책 추가

현재 CMhelper는

```text
고객 이름
전화번호
발송 결과
```

를 다루게 됩니다.

로그 정책이 필요합니다.

예시

```md
Log Policy

허용

발송 성공
발송 실패
오류 코드

금지

전화번호 전체 저장
메시지 전문 저장
개인정보 원문 저장
```

---

# 6. AI 프롬프트 템플릿 추가

현재 AI 지침은 좋은데

실제로 안티그래비티에 매번 붙여넣을 문장이 필요합니다.

예시

```text
작업 시작 전

1.
AGENTS.md 읽기

2.
PROJECT_OVERVIEW.md 읽기

3.
ARCHITECTURE.md 읽기

4.
CURRENT_STATUS.md 읽기

5.
TODO.md 읽기

현재 상태를 요약한 후
작업 계획을 먼저 제시하고
승인 후 개발 진행
```

---

# 가장 중요한 추가

현재 문서에는

```text
안정성
보안
롤백
```

은 있는데

```text
기능 추가 우선순위
```

가 없습니다.

PROJECT_OVERVIEW에 아래를 넣는 것을 추천합니다.

```md
개발 우선순위

P0
고객 관리
카카오 자동화

P1
예약 발송
발송 이력

P2
블로그 자동화
인스타 자동화

P3
AI 챗봇

P4
견적 시스템
```

---

이걸 넣으면 AI가

```text
챗봇 만들까요?
```

같은 방향 이탈을 덜 하게 됩니다.

---

현재 문서는 충분히 훌륭하지만, 실제로 1~2년 이상 운영할 프로젝트라면 다음 4개를 추가하는 것을 추천합니다.

```text
ADR.md
(왜 그렇게 결정했는지)

ROLLBACK_POLICY.md
(어떻게 되돌릴지)

LOG_POLICY.md
(무엇을 기록할지)

AI_FORBIDDEN_RULES.md
(AI가 하면 안 되는 것)
```

이 4개가 추가되면 단순 "프로젝트 문서"가 아니라 실제 SaaS 개발팀 수준의 운영 체계에 가까워집니다.







네. 훨씬 좋아졌습니다.

이제는 단순한 "프로젝트 설명서"가 아니라 **실제 SaaS 개발팀이 사용할 수 있는 운영 헌법 수준**에 가까워졌습니다.

현재 기준으로는 **92~95점 정도**라고 봅니다.

특히 좋은 부분은 다음입니다.

### 잘된 점

✅ AI 금지 행동 명시

✅ 개발 우선순위(P0~P4)

✅ Definition of Done

✅ Rollback Policy

✅ ADR 추가

✅ CURRENT_STATUS 템플릿 강제

✅ AI 작업 템플릿 제공

이 정도면 안티그래비티, Claude Code, Cursor, GPT Codex 계열을 번갈아 써도 프로젝트 맥락 유지가 가능합니다.

# 추가하면 좋은 것 (실제 운영 관점)

## 1. 버전 고정 정책 추가

현재 문서에는

```markdown
Python 3.10.x
PyInstaller 5.x
```

정도만 있습니다.

그런데 AI들은 종종

```bash
pip install --upgrade
```

를 해버립니다.

그래서 AGENTS.md에 추가 추천

```markdown
### Dependency Policy

AI는 사용자의 승인 없이
라이브러리 버전을 업그레이드하지 않는다.

requirements.txt
package.json

버전 변경 시

1. 변경 이유 설명
2. 영향 분석
3. 승인 후 진행
```

---

## 2. 테스트 정책

현재는

```markdown
로컬 테스트 성공
```

정도입니다.

추천 추가

```markdown
### Testing Policy

기능 추가 시

1. 정상 시나리오
2. 실패 시나리오
3. 예외 시나리오

3가지를 모두 테스트한다.

"실행해보면 될 것 같다"는
완료 기준이 아니다.
```

---

## 3. 카카오 자동화 특화 규칙

이건 CMhelper에 매우 중요합니다.

추천 추가

```markdown
### Kakao Automation Safety

1.
한 번의 실패로
전체 발송을 중단하지 않는다.

2.
실패 고객은
Retry Queue에 저장한다.

3.
발송 결과는

SUCCESS
FAILED
SKIPPED

로 구분한다.

4.
현재 고객과 다음 고객이
섞이지 않도록 한다.
```

---

## 4. 장애 등급

SaaS 운영 시 굉장히 유용합니다.

```markdown
### Incident Severity

P1
서비스 전체 중단

P2
핵심 기능 장애

P3
일부 기능 오류

P4
UI 문제
```

그러면 AI도

```text
이건 P1입니다.
즉시 롤백 권장
```

같이 판단할 수 있습니다.

---

# 가장 추천하는 추가 항목

현재 문서에서 딱 하나만 더 넣으라면

## RELEASE.md

추가를 추천합니다.

현재

```text
PROJECT_OVERVIEW
CURRENT_STATUS
ADR
CHANGELOG
TODO
```

까지는 있는데

"출시 기준"이 없습니다.

---

예시

```markdown
# RELEASE.md

v0.1

완료

- 카카오 실행
- 검색
- 채팅방 진입

미완료

- 예약 발송

Known Issues

- 해상도 125% 미지원

배포 여부

- 내부 테스트만
```

---

그러면 나중에

```text
v0.7
v0.8
v1.0
```

갈 때 엄청 도움이 됩니다.

---

제가 CMhelper 관점에서 최종 평가하면,

현재 문서는 **1인 개발자 + AI 협업 체계로는 상당히 잘 설계되어 있고 바로 사용 가능한 수준**입니다.

여기에

```text
RELEASE.md
Dependency Policy
Testing Policy
Kakao Automation Safety
Incident Severity
```

5개만 추가하면 사실상 소규모 SaaS 개발팀 운영 문서 수준까지 올라갑니다.
