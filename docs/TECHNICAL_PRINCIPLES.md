# 기술 원칙 (Technical Principles)

본 문서는 CMhelper 프로젝트의 설계 및 구현에 있어 모든 에이전트와 개발자가 준수해야 하는 핵심 기술 원칙을 정의합니다.

## Core Principles

### 1. Server First
- **목적:** 데이터 및 비즈니스 로직의 단일 진실 공급원(Single Source of Truth)을 서버에 두어 무결성을 유지합니다.
- **적용 방법:** 클라이언트(Frontend, Agent)는 상태를 소유하지 않으며, 서버의 응답을 그대로 반영합니다.
- **적용 사례:** `Remote Config`를 통한 UI 식별자 중앙 관리.

### 2. Thin Client
- **목적:** 클라이언트 단의 복잡성을 최소화하여 유지보수 비용을 줄입니다.
- **적용 방법:** 프론트엔드는 렌더링에만 집중하고, 복잡한 데이터 가공은 백엔드에서 처리 후 전달합니다.
- **적용 사례:** 기존 `fetch` 기반 `req()` 함수를 그대로 사용하여 무거운 라이브러리(Axios 등) 도입 배제.

### 3. Backward Compatibility (하위 호환성)
- **목적:** 새로운 기능을 추가할 때 기존 시스템 및 사용자의 작업 흐름을 방해하지 않습니다.
- **적용 방법:** API 변경 시 기존 동작을 파괴하지 않도록 설계하고, 인증 추가 시에도 기존 라우트의 동작을 강제로 차단하지 않습니다.
- **적용 사례:** 인증 토큰 검증은 인증이 필요한 특정 API에만 국한하며 기존 에이전트 통신 규격은 유지.

### 4. No Hardcoding
- **목적:** 설정값의 변경이 코드 배포를 유발하지 않도록 합니다.
- **적용 방법:** 식별자, 시크릿 키, 기본값 등을 소스코드 내에 문자열 상수로 넣지 않습니다.
- **적용 사례:** 카카오톡 UI 버튼 이름 변경 시 `Remote Config`에서 관리.

### 5. Environment Variable (환경 변수)
- **목적:** 배포 환경(Dev, Prod 등)별로 달라지는 값을 안전하게 주입합니다.
- **적용 방법:** 민감한 값(Secret Key, Invite Code 등)은 `.env` 및 환경변수 주입을 통해서만 읽어옵니다.
- **적용 사례:** `JWT_SECRET_KEY` 및 `CMHELPER_INVITE_CODE` 환경변수 처리.

### 6. Feature Flag
- **목적:** 미완성된 기능이 운영 환경에 영향을 미치지 않게 통제합니다.
- **적용 방법:** 환경변수나 설정값으로 기능의 On/Off를 제어할 수 있게 구성합니다.
- **적용 사례:** 향후 신규 AI 모델이나 발송 로직 적용 시 플래그로 롤아웃 조절.

### 7. Fail Fast
- **목적:** 치명적 설정 누락이나 오류 상황 시 불안정한 상태로 동작하는 것을 막고 즉시 종료하여 런타임 오류 파급을 차단합니다.
- **적용 방법:** 서버 구동 시 필수 환경변수나 DB 연결 상태를 확인하고 문제 시 Exception 발생 혹은 프로세스 종료(`sys.exit(1)`).
- **적용 사례:** `JWT_SECRET_KEY` 미설정 시 서버 시작 중단 처리.

### 8. Single Source of Truth
- **목적:** 동일한 의미의 데이터나 상태가 여러 곳에 중복 저장되어 불일치가 발생하는 것을 방지합니다.
- **적용 방법:** 클라이언트 로컬 상태(Storage)를 맹신하지 않고, 서버 DB 상태를 기준으로 인가/권한을 판단합니다.
- **적용 사례:** `/auth/me` 호출 시 토큰 payload만 믿지 않고 `UserStatus` 및 `CompanyStatus`가 `ACTIVE`인지 DB 재확인.

### 9. Single Responsibility (단일 책임 원칙)
- **목적:** 코드의 결합도를 낮추고 응집도를 높여 재사용성과 테스트 용이성을 확보합니다.
- **적용 방법:** 하나의 함수, 클래스, 모듈은 단 하나의 명확한 책임만을 가집니다.
- **적용 사례:** `crud.py`는 데이터 접근에만, `main.py` 라우터는 요청/응답 분기에만 집중.

### 10. Stateless API
- **목적:** 서버 확장이 쉽고 클라이언트와 서버 간 의존성을 제거합니다.
- **적용 방법:** RESTful API 원칙을 따르며, 요청 시 인증 토큰 등 필요한 모든 컨텍스트를 담아 보냅니다.
- **적용 사례:** 세션 대신 `Authorization: Bearer <Token>` 방식을 사용한 JWT 인증.

### 11. Repository Pattern
- **목적:** 비즈니스 로직이 특정 DB 프레임워크나 저장소 세부 구현에 종속되는 것을 막습니다.
- **적용 방법:** DB 접근은 `crud.py` 등의 별도 계층에서만 수행하며, 라우터는 ORM 객체가 아닌 Pydantic 스키마를 반환합니다.
- **적용 사례:** `create_user` 등의 함수로 데이터 접근 로직 캡슐화.

### 12. Audit Logging
- **목적:** 시스템의 주요 상태 변경이나 장애 원인을 추적할 수 있도록 합니다.
- **적용 방법:** 성공, 실패, 에러 코드를 로깅하되 PII(개인정보) 및 비밀값은 철저히 마스킹합니다.
- **적용 사례:** 발송 성공 여부는 남기되 상담 원문 등은 식별되지 않도록 로그 배제.

### 13. Security by Default
- **목적:** 개발자가 별도의 신경을 쓰지 않아도 기본 설정이 가장 안전한 상태가 되도록 합니다.
- **적용 방법:** 공개 가입 기본값 차단, 비밀번호 최소 8자리 강제.
- **적용 사례:** `CMHELPER_INVITE_CODE`가 일치할 때만 가입을 허용하는 폐쇄형 가입 기본 적용.
