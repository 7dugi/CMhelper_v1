# CMhelper Product Roadmap

## 1. Product Vision

CMhelper는 단순한 고객관리 프로그램을 넘어, 자동차 영업 담당자가 고객 확보부터 상담, 견적, 계약, 고객 관리, 메시지 발송, 광고 콘텐츠 제작, AI 상담, 재고 탐색 및 알림, 마케팅 관리에 이르기까지 모든 프로세스를 하나의 시스템에서 처리할 수 있는 **자동차 영업 업무 특화 플랫폼**으로 발전시키는 것을 장기 목표로 합니다.

가장 중요한 원칙은 **"화려한 AI 기능보다 영업 업무의 뼈대가 되는 기능을 먼저 완성한다."** 입니다. 따라서 CRM, 고객/상담/계약 관리, 카카오 메시지 발송, 권한 관리(RBAC), 데이터 보존 등 뼈대 기능을 최우선으로 구축하며 AI 및 광고 자동화는 그 기반 위에 단계적으로 추가합니다.

---

## 2. Development Principles

1. **Core First**: CRM과 실제 영업 Workflow를 먼저 완성합니다.
2. **AI Later, but AI-Ready**: AI 기능을 무리하게 먼저 만들지 않지만, 향후 AI 연결이 가능하도록 데이터 구조와 API를 사전에 설계합니다.
3. **Human Approval**: 계약, 금융 조건, 중요한 고객 액션 등은 반드시 사람의 확인과 승인을 거치도록 설계합니다.
4. **Korean First UI**: 사용자에게 표시되는 모든 주요 기능명, 상태명, 버튼, 오류 메시지 등은 한글을 기본으로 합니다. (단, Backend Enum 및 API 내부 값은 영어 사용 가능)
5. **Data Retention**: 상담, 견적, 계약 등 영업 이력은 쉽게 Hard Delete되지 않도록 보호합니다.
6. **Tenant Isolation**: 회사별 데이터 격리를 최우선 보안 원칙으로 강력히 유지합니다.
7. **OWNER / USER RBAC**: 사용자 권한 관리는 Backend에서 강제합니다. Frontend에서의 UI 숨김만으로 보안을 구현하지 않습니다.
8. **Incremental Development**: 한 번에 큰 기능을 만들지 않고, `Foundation → Backend → Security Review → Test → Production Migration → Frontend → Runtime Verification` 의 체계적인 점진적 단계를 거쳐 개발합니다.
9. **Changeable Roadmap**: ROADMAP은 고정된 계약서가 아닙니다. 사용자 요구, 실제 사용 경험, 기술 변화, 사업 방향 등에 따라 우선순위와 기능을 유연하게 변경할 수 있습니다. 단, 변경 시 기존 데이터 구조와 보안 원칙을 훼손하지 않아야 합니다.

## 4. Development Priorities

### 우선순위 1 — CRM 핵심 기반 완성
현재 가장 중요한 핵심 개발 영역입니다.
- **포함 기능**: 고객 관리, 고객 상세 화면, 상담(Opportunity) 관리, 상담 메모, 상담 상태 관리, 담당자 관리, 상담 이력, 계약 관리, 고객 ↔ 상담 ↔ 계약 간의 관계 설정, OWNER/USER 권한 적용, Tenant Isolation, 데이터 보존 정책, 검색/필터, 기본 Dashboard 개선.
- **상태 정책**: 상담 상태의 내부 Enum 값은 Backend 기준을 유지하되 사용자 UI는 반드시 한글로 변환하여 표시합니다 (신규 상담, 견적 진행, 협의 중, 계약 확정, 계약 실패, 보류). Raw Enum 노출은 금지됩니다.

### 우선순위 2 — 카카오 메시지 및 고객 커뮤니케이션
CMhelper의 실제 영업 활용도를 극대화하는 핵심 기능입니다. 기존 설계 및 보안 원칙을 엄수합니다.
- **포함 기능**: 고객에게 카카오 메시지 발송, 고객 선택 후 메시지 작성, 메시지 템플릿 제공, 상담/계약 상태 기반 맞춤 메시지, 발송 이력 추적, 고객별 커뮤니케이션 기록.
- **향후 확장**: 자동 발송 및 예약 발송.
- **보안/금지사항**: 카카오 공식 API 또는 비공식 자동화(UIAutomation 등) 활용 시 기존 AGENTS.md에 정의된 충돌 방지, Timeout/Retry 정책, 데이터 격리 원칙을 준수합니다.

### 우선순위 3 — OWNER / USER 운영 기능 강화
기존 구현된 RBAC를 실제 B2B SaaS 운영 수준으로 고도화합니다.
- **포함 기능**: OWNER 사용자 관리 (직원 초대, 활성/비활성 처리, 담당자 변경), 사용자별 고객/상담 데이터 관리, 사용자별 실적 통계, OWNER 전용 전체 현황 뷰, USER 자기 데이터 중심 대시보드.
- **보안 원칙**: 회사별 완전 격리 원칙을 절대 약화시키지 않습니다.

### 우선순위 4 — 기본 견적 기능 (할부/일시불 중심)
견적 기능은 단계적으로 접근합니다. 장기렌트/리스의 복잡한 로직 구현 전에 기본 뼈대를 우선합니다.
- **초기 구현 목표**: 견적 메모, 차량 정보, 상품 유형, 기본 금액 설정, **할부/일시불 중심 견적**, 견적 저장, 상담과 견적 데이터 연결.
- **후기 구현 목표**: 장기렌트/리스 계산, 금융사별 조건(잔가, 금리, 수수료, 프로모션) 연동, 다중 비교 견적.

### 우선순위 5 — 광고 템플릿 / 맞춤 이미지 생성
AI 상담보다 우선순위를 높게 설정하여 영업 업무에 즉시 활용될 수 있도록 합니다.
- **목표**: 사용자가 차량 정보(차량명, 가격, 프로모션, 딜러 정보 등)를 입력하면 영업/마케팅용 콘텐츠(인스타그램 이미지, 블로그/상담용 이미지, 프로모션 카드 등)를 자동 생성.
- **접근 방식**: 
  1. 초기에는 **미리 만들어진 템플릿 기반** 자동 생성.
  2. 향후 **AI를 이용한 맞춤형 이미지 생성** 및 동영상 광고 생성까지 확장. Architecture 설계 시 확장성을 고려합니다.

### 우선순위 6 — AI 상담 챗봇
1차 고객 상담을 지원하는 영업 보조 AI Agent입니다.
- **단계적 확장**:
  - 1단계: 기본 FAQ, 상품 유형 차이, 필요 서류 및 계약 절차 등 안내.
  - 2단계: 고객 요구사항 및 예산 파악, 기본 차량 추천.
  - 3단계: CRM 고객정보 연계, 상담 내용 자동 저장, Opportunity 생성 및 요약.
  - 4단계: 상담 품질 개선 및 Human Handoff(실제 담당자에게 원활한 인계).
- **제한 사항**: AI가 임의로 계약을 확정하거나 중요한 금융/견적 조건을 독단적으로 결정하지 않도록 강력한 통제를 둡니다.

### 우선순위 7 — 블로그 / 인스타그램 관리 및 자동화
생성된 광고 콘텐츠를 실제 채널에 쉽게 관리하고 배포하는 기능입니다.
- **포함 기능**: 콘텐츠 및 캘린더 관리, 게시 예정/이력 추적, 다채널(Instagram, Blog 등) 연동, 예약/반복 캠페인 관리.
- **권장 Architecture (Hybrid)**:
  - **CMhelper Web (Control Plane)**: 콘텐츠, 템플릿, 캠페인 및 데이터 관리는 웹 SaaS에서 처리.
  - **Local Helper (Execution Agent)**: 브라우저 자동화 등 로컬 환경이 필수적인 실행 작업만 별도 데스크톱/로컬 에이전트로 분리.

### 우선순위 8 — 차량 재고 관리 / 검색 / 알림
실무에서 가장 중요한 오프라인 재고 매칭 기능입니다.
- **포함 기능**: 차량 재고 등록(브랜드, 모델, 트림, 색상, 옵션 등), 출고 가능 시기 파악, 검색 및 필터링.
- **핵심 목표 기능 (Inventory Watch)**: 사용자가 원하는 차량 조건을 등록해두면, 조건에 맞는 재고가 입고(발견)되었을 때 자동 알림을 전송하는 시스템. (향후 AI 상담 챗봇과 연결하여 고객 요청 시 자동 등록 및 매칭 후 담당자 알림 구조로 발전)

### 우선순위 9 — 장기렌트 / 리스 고급 견적 시스템
금융사별 복잡도(잔가, IRR, 금리, 수수료, 프로모션 등)가 높으므로 CRM 안정화 이후 마지막 단계로 진행합니다.
- **목표**: 렌트사/리스사별 정확한 견적 계산 및 금융사별 상세 조건 자동 비교.

## 5. Current UX Issues

현재 Phase 3C 구현 상태에서 발견되었거나 다음 Phase에서 개선이 필요한 UX/UI 관련 이슈 및 과제들입니다.

- 견적 추가 화면 내 저장 버튼 및 UX 흐름 점검 필요.
- 견적 입력 항목이 실제 초기 영업 흐름에 비해 과도할 수 있으므로, 초기 견적은 상세 금융 계산보다 '상담 메모' 중심으로 단순화하는 방안 고려.
- 상담 상태를 '계약 확정(WON)'으로 변경 시 실제 Contract를 생성/전환하는 명시적인 사용자 Workflow 부재.
  - **해결 원칙**: WON 상태 변경만으로 Contract를 자동 생성해서는 안 되며, 별도의 명시적 '계약 전환' 사용자 액션을 거치도록 개선해야 함.
- Customer Detail 화면 내 불필요하거나 의미가 불명확한 UI 요소 점검 및 정돈 필요.

## 6. Future Architecture Candidates

광고 및 마케팅 채널 자동화를 위한 Hybrid Architecture 후보:
- **OPTION A**: CMhelper Web SaaS 내부에서 직접 외부 API 연동 수행 (제한적 자동화).
- **OPTION B**: 별도의 Local/Desktop Marketing Tool을 구성 (기반 기술: UIAutomation/OpenCV).
- **최우선 권장안 (Hybrid Control Plane)**: 사용자 데이터 및 템플릿 관리는 Web(SaaS)에 두되, 실제 자동화 실행은 보안과 세밀한 조작이 가능한 Local Helper(Execution Agent)가 분담하는 구조를 지향합니다.

## 7. Long-Term Vision

CMhelper는 지속적인 데이터 축적을 통해 영업 프로세스의 자동화를 넘어, 각 딜러와 영업 담당자에게 **데이터 기반 의사결정**을 지원하고 고객 전환율을 극대화하는 것을 최종 지향점으로 삼습니다. 단기적인 효율성 증대뿐 아니라 장기적인 고객 관계 강화(Customer Relationship Management) 플랫폼으로 확고히 자리 잡을 것입니다.

우선순위 1~9에 포함되지 않은 **향후 확장 핵심 기능(장기 로드맵)**은 다음과 같습니다:
- **영업 Pipeline 및 Loss Reason 분석**: 상담 실패 사유를 분석하고 전환율을 추적하여 영업 효율 개선.
- **고객 Portal**: 고객이 직접 자신의 견적, 계약 상태, 만기일, 차량 반납/인수 시뮬레이션을 확인할 수 있는 전용 웹페이지.
- **만기 및 재계약 관리**: 기존 계약의 만기 도래 전 사전 알림 및 재계약 유도 프로세스 자동화.
- **Excel/CSV Import**: 기존 영업 데이터를 대량으로 쉽게 이관할 수 있는 도구.
- **SaaS Billing & Entitlement**: B2B SaaS 구독 플랜, 과금 체계 및 권한(Entitlement) 자동화.
- **고급 통계 및 Analytics (Aggregated Analytics)**: 금융사 및 제조사용 비식별 집계 통계 제공.
