# 리스크 관리 대장 (Risk Register)

본 문서는 CMhelper B2B SaaS 플랫폼 확장 및 운영 과정에서 발생할 수 있는 주요 리스크 요소를 식별하고 예방 조치 및 대응 전략을 정의합니다.

## 1. 운영 및 시스템 리스크

### 1.1 오발송 (잘못된 대상/내용 전송)
- **발생 가능성:** 중간
- **영향도:** 높음 (P1/P2)
- **예방 조치:** 채팅방 진입 후 윈도우 타이틀 이름과 DB의 고객명 이중 교차 검증 (현재 로직 적용 완료).
- **발생 시 대응:** 긴급 에이전트 정지(Freeze), 에러 로그 확보 및 오발송 안내 문자 수동 발송 가이드 제공.
- **상태:** 모니터링 중 (이름 검증 로직 구현됨)

### 1.2 서버와 Agent 상태 불일치 (Orphan Task)
- **발생 가능성:** 중간
- **영향도:** 중간 (발송 지연)
- **예방 조치:** 백엔드와 에이전트 간 3분 단위 Heartbeat 생존 신호 교환 및 자동 복구(`RECOVERY`) 스케줄링.
- **발생 시 대응:** 백엔드의 5분 이상 응답 없는 작업 자동 초기화 및 재시도 큐 배치.
- **상태:** 완화됨 (V4.1 로직 구현, 테스트 대기)

### 1.3 카카오 정책 또는 계정 제한
- **발생 가능성:** 낮음
- **영향도:** 매우 높음 (치명적)
- **예방 조치:** 맹목적인 기계적 API 호출 대신 실제 인간의 마우스/키보드 패턴을 흉내내는 딜레이 적용 및 로컬 기반 백그라운드 구동.
- **발생 시 대응:** 서비스 공지 및 어뷰징 기준 확인, 발송 인터벌 및 딜레이 튜닝 긴급 패치.
- **상태:** 상시 감시

### 1.4 로컬 SQLite DB 손상
- **발생 가능성:** 낮음
- **영향도:** 높음
- **예방 조치:** 개발 및 초기 배포에만 SQLite를 사용하며, 빠른 시일 내 클라우드(PostgreSQL/Supabase)로 전환.
- **발생 시 대응:** `.db` 백업 파일 롤백.
- **상태:** 향후 이전 계획(Target Architecture) 수립됨

### 1.5 동명이인 식별 실패
- **발생 가능성:** 중간
- **영향도:** 높음 (오발송 리스크)
- **예방 조치:** 카카오톡 채팅방 내 전화번호 매칭 또는 프로필 해시 검증 방안 추가 기획 필요.
- **발생 시 대응:** 동명이인 발견 시 수동 확인 팝업 알림 띄우기 처리.
- **상태:** 완화 방안 추가 기획 필요 (Open Issue)

## 2. 보안 및 데이터 리스크

### 2.1 로그/백업 내 개인정보 노출 (PII)
- **발생 가능성:** 낮음
- **영향도:** 매우 높음 (법적 제재)
- **예방 조치:** 파일 로그(FileHandler) 기록 시 전화번호 등 연락처 일절 배제 및 이름 가운데 글자 마스킹(예: 홍*동) 처리.
- **발생 시 대응:** 즉시 서버 셧다운 및 기존 로그 파일 파기, 보안 패치 적용.
- **상태:** 완화됨 (마스킹 로직 V4.1 구현)

### 2.2 금융사/OEM 데이터 이용 권한 문제
- **발생 가능성:** 높음 (향후 플랫폼 확장 시)
- **영향도:** 높음
- **예방 조치:** 크롤링 대신 공식 API 계약 추진 또는 대리점/영업사원이 합법적으로 제공받은 데이터만 취급하는 구조(면책 조항) 마련.
- **발생 시 대응:** 관련 기능 접근 제한 및 법적 검토.
- **상태:** 향후 과제로 관리

## 3. 업데이트 및 배포 리스크

### 3.1 Agent 업데이트 실패
- **발생 가능성:** 낮음
- **영향도:** 중간 (구버전 파편화)
- **예방 조치:** 자동 업데이트 런처(Auto Update) 도입 전까지 사용자가 다운로드 링크로 직접 패치하도록 공지.
- **발생 시 대응:** 롤백 버전(구버전) 실행 파일 다운로드 링크 긴급 제공.
- **상태:** Auto Update 파이프라인 구축 대기

### 3.2 Remote Config 오배포
- **발생 가능성:** 낮음
- **영향도:** 전체 에이전트 마비 (P1)
- **예방 조치:** Remote Config 배포 전 Canary Test 자동 구동으로 100% 성공 시에만 설정 릴리즈하는 파이프라인 도입.
- **발생 시 대응:** 백엔드 어드민에서 이전 Config 버전으로 즉각 롤백.
- **상태:** 파이프라인 기획 단계

### 3.3 DB 마이그레이션 실패
- **발생 가능성:** 중간
- **영향도:** 매우 높음 (데이터 유실)
- **예방 조치:** `Customer` 단일 테이블을 `Opportunity` 및 `Contract`로 분리하기 전, 스냅샷 백업 및 staging 서버(테스트 데이터베이스)에서 사전 스키마 변경 시뮬레이션 필수 진행.
- **발생 시 대응:** 배포 롤백 및 기존 스냅샷 DB 복원.
- **상태:** 미래 확장 대비 주의 항목
